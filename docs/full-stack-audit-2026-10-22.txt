3. ARCHITECTURE FINDINGS

The local-first modular monolith has useful separation between routers, graph extraction, providers, review storage and agent tools. Shared frontend graph context supports multiple views. Existing review decisions bind to a revision and digest; model tools do not directly perform writes. Those are source/test observations, not enterprise assurance.

Confirmed cross-layer inconsistencies were domain inference (AUD-002), IPv6 host normalization (AUD-005), and sync dependency teardown relying on worker-thread identity (AUD-006). Domain normalization is now shared across backend materialization, managed snapshots, retrieval and citations, preserving explicit provider domains. SQLite capacity release now carries its acquired lease across worker threads.

Architectural risks, distinct from demonstrated bugs:
  R-01: Session bearer tokens isolate reviewers but are not user identity, RBAC or independent approval. Loopback is the supported default; externally exposed deployments require an authenticated TLS gateway and suitable process/file protections.
  R-02: Request parsing can allocate JSON before source-content limits are evaluated. Analysis deadlines cannot interrupt every Python parser operation mid-file. Gateway request-body limits and adversarial resource testing remain deployment work.
  R-03: SQLite leases depend on renewal. Prolonged renewal/storage failure could permit expiry while work continues. Cross-thread teardown is tested; renewal-loss overlap is not fault-injected here.
  R-04: Provider/agent modules combine several responsibilities and share settings/store state. Maintainability refactoring is deferred to avoid unrelated changes.
  R-05: /health is local liveness and does not prove external AI/provider/database readiness.
  R-06: Import indexing alone cannot prove all circular dependencies or dead-code reachability. No exhaustive cycle/dead-code elimination claim is made.
