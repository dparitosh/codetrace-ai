OA-01 | Medium / P2 | Agent / Tool contract | Confirmed
Location: backend/services/agent_workspace.py:59-70, tool_schema / ToolInput / tool.
Description: inspect_resource, traverse_graph and similar_resources use a shared schema
in which node_id defaults to an empty string and is not required. Runtime requires
a node present in the snapshot. Empty arguments conform to the advertised schema
but fail execution and can terminate the model run into evidence fallback.
Evidence: probe validates ToolInput({}), confirms node_id absent from schema.required,
then reproduces ValueError from inspect_resource({}).
Root cause: one generic input model supplies optional fields to every tool.
Impact: preventable invalid calls and reduced tool reliability even for a model that
obeys the provided JSON schema; not a shell or authorization bypass.
Fix: tool-specific schemas with required node_id for resource tools and corresponding
runtime validation. Advertise only relevant parameters for each tool.
Validation: validate omitted identity against each schema; valid identifiers must
execute; missing/foreign identities must fail without executing a tool.

OA-02 | Medium / P2 | Agent / Evidence correctness | Confirmed
Location: backend/services/agent_workspace.py:296, GraphAgent.run fallback.
Description: fallback passes an empty edge list to evidence_answer even after an
executed traversal observed explicit relationships. It then says no non-containment
relationship was found in the retrieved context.
Evidence: a mocked model first requests a successful directed traversal, then fails.
The trace includes related nodes but the resulting fallback says no relationship found.
Root cause: accumulated node citations are retained; observed relationship evidence
is not carried into deterministic answer generation.
Impact: misleading explanation during exactly the outage/invalid-response scenario
where the user must rely on retained graph facts.
Fix: retain bounded observed relationships with citation endpoints and pass them into
fallback generation. Do not infer unseen links from the entire graph.
Validation: traverse -> model failure must still report the observed relationships;
an isolated resource must continue to report absence only within the retrieved context.

OA-03 | Medium / P2 | Backend / Malformed response handling | Confirmed
Location: backend/services/ai_connection.py:172-174, OllamaREST.embed.
Description: valid JSON may contain an integer too large to convert to a floating
point number. math.isfinite(value) raises OverflowError for 10**400. The embedding
validator and lexical fallback exception handlers do not handle this exception.
Evidence: a mocked /api/embed response containing [[10**400,1]] raises OverflowError;
the same response escapes /workspace/search rather than returning lexical results.
Root cause: numeric type checking precedes an unchecked float conversion inside the
finite-value test; finite JSON integer is not necessarily representable as float.
Impact: malformed/provider-generated numeric data can cause a server error instead
of the intended controlled rejection and fallback. The endpoint remains allowlisted.
Fix: reject nonrepresentable/magnitude-invalid numbers as ValueError; validate the
normalization calculation without unchecked integer-to-float conversion.
Validation: huge integers, infinity, NaN, booleans, zero vectors and mixed dimensions
must fail predictably; search should retain explicit lexical evidence on failure.

OA-04 | Medium / P2 | Integration / Diagnostics | Confirmed
Location: backend/api/workspace_routes.py:112-113, test_ai.
Description: Save and test chat + embeddings first calls GET /api/tags. A gateway
with working POST /api/chat but no discovery route fails before chat is exercised.
Evidence: mock returns 404 for /api/tags and a valid ready response for /api/chat;
the endpoint returns 502 and only /api/tags is called (memory and SQLite sessions).
Root cause: discovery is an unconditional prerequisite of the connectivity test.
Impact: usable restricted REST gateways appear completely broken; the returned
message incorrectly frames this as a chat/embedding/model/key failure.
Fix: separate discovery results from chat/embedding readiness; support explicit
discovery policy and preserve honest per-operation outcomes. Do not claim discovery
succeeded when unavailable or swallow authentication failures as successful tests.
Validation: missing tags + working chat must report the separate outcomes; missing
chat, failed authentication and failed embeddings must remain actionable failures.

DISCLOSED CAPABILITY LIMITATION — NOT COUNTED AS A NEW DEFECT
Location: backend/api/workspace_routes.py:113,121; services/ai_connection.py:179.
The connectivity test sends no tools. A mocked model that accepts plain chat but
rejects every tools request still returns chat=ready. The API explicitly warns that
tool quality is checked during agent execution, so this is not a false promise of
verified tool support. The UI flow nevertheless offers no tool-capability preflight.
Native tool support and grounded JSON output are both needed for model-led agents.
Proposed improvement: separate model connectivity and a harmless read-only tool
round-trip status; keep connectivity success distinct from agent readiness.
Actual compatibility of the user's installed model was not tested or inferred.

COMPATIBILITY RISK — UNVERIFIED RUNTIME IMPACT
At services/agent_workspace.py:276, the assistant tool-call message is reconstructed
with only role, truncated content and tool_calls. Other returned fields, including
thinking, are discarded. Ollama's official agent-loop examples retain response.message.
Some model/template combinations may depend on retaining that context. Omission is
visible in code, but a model-specific failure was not reproduced; do not count it as
a confirmed production failure. Preserve protocol fields only within byte budgets
and avoid adding private reasoning to user-facing logs or exports.
Reference: https://docs.ollama.com/capabilities/tool-calling
