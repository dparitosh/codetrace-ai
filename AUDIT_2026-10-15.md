## Siemens iX implementation

Uses official `@siemens/ix`, `@siemens/ix-react` and `@siemens/ix-icons` packages. Main shell is IxApplication/IxApplicationHeader/IxMenu/IxContent, with pinned navigation, menu categories, theme switching, avatar, source selector and Siemens buttons for graph/review/session actions. Cytoscape remains the graph engine and consumes public theme colors. Companion, metrics and inspectors use iX tokens. Existing local analysis forms remain available within this shell.

References: [Siemens React installation](https://ix.siemens.io/docs/home/installation/react), [Siemens React starter](https://github.com/siemens/ix-starter/tree/main/apps/react-starter), [Tailwind upgrade guide](https://tailwindcss.com/docs/upgrade-guide).

## Remaining gaps

- P1: Git checkout still trusts host Git configuration/credential helpers; clone isolation remains required before accepting untrusted repository administration.
- P2: SBOM import/generation is not implemented in the mounted local API; legacy models alone do not provide SBOM compliance.
- P2: Review sessions remain process-local; durable publication does not provide shared multi-worker sessions.
- P2: TRS consumption is bounded snapshot reconstruction, not durable incremental replay; published bases retain a count-based window. CI evidence is bounded to one configured response/window.
- P2: Full in-app OSLC link-proposal approval/apply/reconcile workflow and live Polarion/Codebeamer verification remain incomplete.
- P2: Existing PostgreSQL schemas still need versioned migrations for long resource identifiers, graph-scoped uniqueness and endpoint constraints. Bootstrap does not alter existing columns.
- P2: Legacy database fallback can turn failed queries into empty/None results; it is not wired into current active sessions/publication.
- P3: Siemens iX payload and dense high-degree layouts need further performance/readability work. Label clipping is intentional in canvas previews; inspector retains identity and provenance.
- Live PostgreSQL, ALM vendor servers and real Ollama inference were not available for integration tests. Local graph evidence fallback remains functional.

## Installation requirements

The patched test stack requires Node 22.12+ (22.x), 24.x or 26+; CI uses 24. Run npm ci inside frontend. Tailwind 4 assumes modern browsers. Source, configuration and lockfile changes are preserved; temporary test services/dependencies are removed after verification per the user's earlier instruction.
